# QREX Android — Screen 11: Privacy / Politika privatnosti

**Date:** 30 October 2026
**Scope:** Existing open [QREX PR #80](https://github.com/bren-wp/QREX/pull/80); no new branch, application version bump or signing change.

## UI, accessibility and reference scope

The native Material 3 Privacy dialog now has a localized bold title, a scrollable disclosure card with a 22dp Shield icon, and a separate settings card containing the real local History switch. It preserves QREX's shared card radius, theme colors and spacing, with 14dp message padding and a minimum 64dp settings row. The dialog's **Close** and **Read full policy** actions remain outside the scrolling copy, each at least 48dp high, so a long 23-language translation does not trap users or hide the exit.

This is still the production Privacy dialog available from the More tab; it is not a disconnected layout prototype. Content uses existing `privacy_summary`, `save_history`, `privacy_policy`, `close` and `read_full_policy` translations. The existing external policy destination remains an explicit secondary action; opening the dialog or toggling History never opens a browser.

**Pixel parity limitation:** The original reference boards are not flat, registered PNG references of identical device size, typeface, language, theme, version, and state. Do not claim literal 1:1 until actual pixels are compared and the difference is recorded. Existing `tool/compare_ui_pixels.py --screen privacy` now accepts `android-privacy.png` as an audit target and fails for changed pixels.

## Storage/consent guarantees

- The History switch is a real native `Switch`, tagged `qrex-privacy-history-switch`; its selected state comes from `store.historyEnabled`, not a decorative preview.
- Its existing `store.updateHistoryEnabled(enabled)` operation commits a local SharedPreferences boolean before updating observable state. If it fails to commit, it reports a localized failure instead of pretending the preference changed.
- Turning History off prevents subsequent automatic history recording as before; it **does not erase** existing QR records or Favorites. Destructive deletion remains a separate explicit **Clear history** action in More, with confirmation.
- Wi-Fi QR records are never automatically saved, and manually saved Wi-Fi secrets continue to use the existing Android Keystore encryption path. This change does not modify the persistence format, migration logic, manifest permissions or remote data flows.
- The full public policy link stays `https://github.com/bren-wp/QREX/blob/main/docs/PRIVACY.md` and is opened only by an explicit user tap.
