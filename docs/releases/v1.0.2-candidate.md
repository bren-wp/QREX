# QREX 1.0.2 — Historical release-candidate acceptance checklist

**Archived checklist (written before publication).** GitHub **v1.0.2 was published on 20 October 2026** with `versionCode 102`. The Android API emulator matrix, native CI and screenshot checks passed before publication; this does **not** verify Google Play upload identity or physical-device in-place upgrade QA. The published GitHub APK/AAB were signed with a disposable certificate and are **not** compatible in-place updates to earlier GitHub or Play installs. For current release information see [v1.0.2 notes](v1.0.2.md).

The below acceptance gates record the historical candidate risks, including follow-up physical-device and Play requirements. They are preserved as an audit trail, not as the current GitHub release status.

## Candidate content
- Native Android Kotlin/Compose stability work from previously closed, **unmerged** P03 PR #23: result-close layout, 30 Create→Result→Back navigation cycles, independent off-main-thread QR rendering, SAF isolation, safe preview bitmap lifetime, Activity recreation regression.
- Android API 26/31/34/35/36 emulator stress matrix and redacted event counters; generated CI artifacts contain no QR text, SSIDs, Wi-Fi passwords, exception class, stack frame, or raw logcat.
- Required Python redaction unit tests run in each applicable API matrix job.
- Pure Kotlin unit test verifies that valid QR results remain actionable independently of image-preview readiness; saving still waits for a valid preview.

## Release approval gates (must all pass)
1. Review the P03 changes and clear unresolved security/test review findings. Confirm the release branch's final SHA passes Android unit/instrumented tests, lint, R8, merged-manifest check, 23 translations and actual screenshot. All five API emulator matrix jobs need a completed success result; pending, skipped, cancelled or failed means NO RELEASE.
2. **Play Console: NIJE POTVRĐENO.** Check QREX package `com.brendigo.qrex`, actual highest versionCode on every applicable track, app signing certificate fingerprint, upload certificate and release-track status. Do not assume 102 is available. Only after verified, bump versionName/versionCode in a dedicated versioning PR and update `tool/check_native_release.py` + its tests. A disposable CI-signed APK cannot upgrade an existing Play installation.
3. Run real, non-destructive in-place upgrade on a device with same Android-recognized signing identity. Check Flutter migration, favorites, Wi-Fi ciphertext and 250 entries before/after; never uninstall first.
4. Run 30 actual CameraX Scan→Result→Back cycles, picker/permissions, SAF export, rotation and genuine process death on Pixel, Galaxy and a physical low-memory device. Record redacted logs and compare data. CI emulator alone is insufficient.
5. Verify GitHub release script only publishes *after* all gates. Sign with stable expected distribution identity or explicitly mark GitHub APK non-upgradeable. Never reuse or expose the Play signing key. A new GitHub AAB is not a Play Console upload.

**Historical decision:** Do not misrepresent the separately published GitHub v1.0.2 as Google Play-approved or an in-place upgrade. Earlier v1.0.0 and v1.0.1 assets are preserved; outstanding real-device and Play-specific validation remains separately required.
