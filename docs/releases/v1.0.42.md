# QREX 1.0.42 · Android build 142

## Result — more faithful to the provided Android reference

This release includes the merged Result-screen and regression fixes from
[PR #100](https://github.com/bren-wp/QREX/pull/100) with a **new Android
versionCode 142**, rather than republishing build 141.

- **Standalone Result screen:** main five-tab navigation stays hidden
  while the QR Result overlay is displayed, as on the supplied reference.
  Both visible Back and Android system Back return to the previous section.
- **Reference action hierarchy:** Open, Copy, Share, Show QR, Favorite
  and confirmation-protected Delete remain genuine functional actions.
  Edit stays available from the top-right overflow menu and returns to
  the real Create editor with the current payload.
- **Safe URL subtitle:** only an HTTP(S) scheme and hostname are repeated,
  never URL paths, access tokens, queries, fragments or userinfo.
- **Adaptive layout:** narrower viewports and large text use a shorter
  summary card, normal phones use a readable 180dp summary, and tablets
  use 192dp with a centered maximum-width column. Result body scrolls
  independently of the pinned Back/menu header, with IME-safe insets.
- **Full UI regression fix:** after opening a QR Result, exporting PDFs,
  saving Favorites, searching History and navigating main tabs return
  through the visible Back action first. This removes stale test assumptions
  that the bottom tabs were displayed beneath a standalone Result.
- QREX's existing offline CameraX + ZXing scanning, eight QR generation
  types, 23 translations, local History/Favorites storage, Wi-Fi consent
  dialogs, Android Keystore protection and PDF/PNG export behavior are
  preserved.

## Release verification

**Publication is gated on four successful jobs from the same merged-main
commit:** Android native Kotlin/JVM/Lint/R8, localization generation,
verified 12 genuine Android emulator captures and the full P03 lifecycle
suite on Android API 26, 31, 34, 35 and 36.

Required release assets are an APK, AAB, **Play-UNSIGNED-QA** AAB,
12 actual phone screenshot PNGs, and `SHA256SUMS.txt`. The release
workflow checks the exact version code, Android app ID, cryptographic
signatures and matching APK/AAB signing certificates.

The GitHub APK and AAB use a newly generated **disposable CI certificate**,
not the existing Google Play upload identity. A differently signed
installation cannot be upgraded in place, and the QA AAB is not Play
upload-ready. Do not uninstall an existing app before backing up local data.

**Visual integrity:** exact 0% pixel error is not certified because the
supplied reference is a perspective marketing composition instead of a
pixel-aligned flat screenshot from an identically configured device.
Native screen interactions and responsive behavior are tested separately.
