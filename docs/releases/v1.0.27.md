# QREX v1.0.27 — Splash and Scanner UI fidelity

**GitHub release candidate:** v1.0.27 (Android versionCode 127) · package `com.brendigo.qrex` · minSdk 26 · targetSdk 36.

## Native Android screen pass
- **Screen 01 — Splash:** Retains the native Q/QR vector (no marketing mockup substituted), cyan-accented verb in the QREX wordmark/tagline, blue ribbon gradients, anchored footer and compact/large-text layout protections. The CI captures real emulator pixels.
- **Screen 02 — Scanner:** Header now accurately states that scanning happens on the device, as in the supplied design. Translated through all 23 catalog languages with generated Android resources. Original CameraX/ZXing camera/gallery, privacy, torch and zoom behavior is unchanged.
- **Screen 03 — Create QR:** Replaced the duplicate launcher wordmark in the Create header with a centered title, a working 48dp Back-to-Scanner arrow and a tagged overflow menu for E-mail, Phone, Location and Event types. Preserved the separate accessible advanced-type disclosure, responsive choice controls and actual Create/Save actions. Centered the QR thumbnail and placed its Preview label beneath it without repeating potentially sensitive QR payload text. Added instrumented navigation/touch-target/overflow tests and source regression contracts.
- **Quality:** Instrumentation verifies the scanner subtitle and real buttons. Existing tests for QREX storage, gallery, events, release metadata, 23 languages and the API 26/31/34/35/36 matrix remain required.

The user-supplied marketing board includes handset frames and transformed images. Actual device screenshots are checked by CI, but mathematical 1:1 equality with a perspective composite is not claimed; exact pixel comparison requires a flat registered reference image.

- **Screen 04 — Wi-Fi QR:** Android password keyboard, real 48dp Show/Hide action with Compose instrumentation coverage, and exact SSID preservation (including leading/trailing spaces). Original encrypted history and explicit Wi-Fi PNG export consent remain intact. [Screen audit](../audits/2026-11-01-qrex-wifi-create-screen.md).

- **Screen 05 — QR Result:** Wi-Fi copy actions (both main action and overflow menu) now demand explicit consent before placing a password-bearing QR payload on Android's clipboard. The clipboard retains Android's sensitive-content metadata, but is not falsely presented as encrypted or automatically cleared. Removed a redundant second display of potentially tokenized URLs. QR preview controls now switch between "Show QR" and "Hide" as the actual state changes. Added a real emulator cancellation/overflow regression test and a privacy source contract. [Screen audit](../audits/2026-11-02-qrex-result-screen.md).

- **Screen 06 — History:** Cards no longer repeat full QR bodies or token-bearing URL query strings as their subtitle. Generic text QR codes now use a localized category in the title instead of printing their raw text. Full data remains available after opening a Result. Added stable, accessible Delete/Cancel dialog actions, and instrumented tests for search, Saved/All filtering, cancellation, and targeted deletion of a synthetic QR record. Existing Favorites and saved-history data remain untouched. [Screen audit](../audits/2026-11-02-qrex-history-screen.md).

- **Screen 07 — Favorites:** Saved QR rows now show localized QR category and age in the same compact hierarchy as History, without printing raw QR bodies or query tokens. The 48dp favorite/unsave action reports its translated saved status to accessibility services. Existing removal behavior changes only the saved flag and retains the History record; the real-emulator test now checks the Favorites subtitle. [Screen audit](../audits/2026-11-02-qrex-favorites-screen.md).
- **Android 8.0 API 26 regression:** A previous P03 check failed because the Show QR action was below the small Result viewport following IME navigation. The interaction test now performs a real scroll to that action, then verifies the tap and actual generated QR bitmap; the check was not removed. Pending fresh matrix validation.

## Public GitHub distribution only
The publication workflow must first verify the exact `main` commit and successful native, localization and screenshot CI jobs. It builds and signs a release APK/AAB using a disposable CI-only certificate, confirms package/version/signature integrity, generates SHA-256 checksums, collects 12 genuine Android screenshot PNGs, and checks the release tag and assets.

**Important:** The public GitHub APK/AAB certificate is not the existing Google Play upload certificate. It cannot replace an installed Play app and must **not** be submitted as an authorized Play update. The `Play-UNSIGNED-QA.aab` is deliberately not Play-ready. Keep the Play signing key protected and the existing user's saved QR/history data intact.

**Publication status:** This source file is release preparation; do not claim v1.0.27 is published until GitHub confirms the final tag and all assets.
