# QREX v1.0.34 — scanner reference: neon frame and raised controls

**Candidate; not yet published.** App ID `com.brendigo.qrex`, Android versionName `1.0.34`, versionCode `134`. Minimum SDK 26, target 36. Changes are made to real Kotlin/Compose screens, not marketing screenshots.

## Main visual correction: Home / Scanner

After comparing the 1672×941 user reference with authentic 1080×1920 QREX Android emulator captures, the scanning brackets are substantially narrower and dimmer than the reference. The photorealistic desk/laptop in the reference is a marketing scene: CameraX must continue displaying the user's **real camera** and may never substitute that photo.

- Frame side is capped at 73% of viewport width and 83% of usable camera height above action controls, rather than the old 61% of the smaller dimension. Canvas dimensions are finite-checked.
- Corner overlay now draws three layers: deep blue 16dp bloom, bright cyan 7dp glow and a sharp 3dp icy-white line. QR frame remains cosmetic, no decoded frames are stored.
- Floating 56dp CameraX flash toggle gets native 4dp shadow and an opaque dark blue vertical glass gradient; both real flashlight buttons still use the same acknowledged hardware callback.
- Gallery remains Android's privacy-preserving system picker, QR decoding remains local through ZXing, and the real CameraX preview is not cropped or replaced. Bottom action buttons keep their touch size and responsive variants.
- Tests check width/height bounds at regular, short and invalid viewport sizes, real CameraX overlay bounds, hardware callback continuity and native code source constraints.

## QA and publishing gates

Require exact-head Python/JVM source/unit, Kotlin compile, Lint/R8, all P03 Android API 26/31/34/35/36 emulator tests, 23 offline languages, twelve genuine 1080×1920 captures, verified SHA256SUMS and the GitHub API's full 16 release assets (APK, AAB, unsigned Play QA AAB, SHA256SUMS and 12 PNG). No skipped validations, and no pixel-perfect claim from an unrectified marketing composite.

**Signing:** CI uses a disposable identity for GitHub APK/AAB. These packages cannot update Play or differently signed installs in place; Play uploads require the existing approved certificate. The unsigned QA AAB is not Play upload ready.
