# QREX 1.0.0 — Scan. Create. Share.

**Production release notes. Publish this document only after signed Android and iOS artifacts pass all required checks.**

QREX is a local-first QR code scanner and creator for Android and iOS, developed by [Brendigo](https://brendigo.com).

## What's included

- Scan QR codes using the camera or a gallery photo.
- Generate QR codes for URLs, text, Wi-Fi, contacts, email, telephone numbers and locations.
- Preview scanned destinations before opening external links; QR results do not open URLs automatically.
- Save and search QR code history and manually chosen favorites.
- Protect saved Wi-Fi credentials using Android Keystore or iOS Keychain.
- Export QR artwork as PNG and favorite QR codes as printable PDF documents or ZIP archives containing PDF.
- Use a light or dark theme and select from 23 interface languages, including English and Croatian.
- Improve photo scanning resilience by reducing image decoding memory requirements.
- Retain the published Flutter Android history migration path.

## Privacy and limitations

QREX does not require an account and does not send your QR scan history to a QREX cloud service. QR exports and external shares are user initiated. A PDF or ZIP containing saved Wi-Fi QR data is **not encrypted**; choose a trusted destination.

## Distribution integrity

Only the explicitly approved `v1.0.0` GitHub stable release may ship these files:

- `QREX-Android-1.0.0.aab` — signed with the **existing, approved Google Play upload key**, for Play Console submission. AAB files are not ordinary APK installers.
- `QREX-iOS-1.0.0.ipa` — signed for Apple App Store distribution with the **authorized Apple Developer Team and provisioning profile**.
- `SHA256SUMS.txt` — SHA-256 checksums calculated from the actual signed binaries.

Android package ID and iOS bundle ID: `com.brendigo.qrex`. Marketing version: `1.0.0`; build/versionCode: `100`.

**A GitHub release does not itself mean Google Play or the Apple App Store has reviewed, approved or published the application.** Store approval, TestFlight/internal testing, verified upgrade continuity and storefront metadata remain separate requirements.
