# QREX v1.0.51 — Android build 151

**Status:** Published from verified commit 3cd741b46be2e0fd0ddc6d93f683da1daf88f6f0. [GitHub Release v1.0.51](https://github.com/bren-wp/QREX/releases/tag/v1.0.51).

## Document scanning reliability

- Strengthen CameraX capture callback lifecycle: completed background image work returns ownership to the UI main thread, and completed images are discarded when the editor has already closed.
- Clean up document EXIF/resize intermediates on exceptional paths; keep native bitmap allocations bounded and preserve correct 90° / mirrored image orientation.
- Retain manual perspective/rectangle crop, offline edge suggestions, undo, grayscale/BW enhancement, page reordering and eight-page A4 PDF export.

## QR scanning and verification

- Add a conservative center-region decode fallback after the whole-image and inverse-image ZXing passes, for QR codes embedded in larger gallery photos.
- Test real decoder input on inverted and centered QR images and check CameraX luminance plane offsets/row stride.
- Add a real Android JPEG EXIF orientation regression test for imported document photographs.
- Keep five native root tabs, 23 translations, the existing privacy/Keystore model, offline operation and Android minSdk 26.

## Real screenshots and documentation

- Include **12 existing main UI states + 8 dark/light document editor UI states** from the exact-commit emulator capture run as permanent assets (20 PNG images).
- README shows actual Android interface images; the document guide explains the workflow and limitations.
- Screenshots are genuine app pixels with privacy-safe synthetic paper fixture content, not camera photographs or mockups. Full 1:1 pixel parity requires user-provided matching flat reference images.

## Release gates

- Package `com.brendigo.qrex`, versionName `1.0.51`, versionCode `151`, minSdk 26 and targetSdk 36.
- Require all native build/JVM tests, R8/Lint, localization, API 26/31/34/35/36 instrumentation, real emulator screenshots, 20 image dimension checks, APK/AAB signature matching and SHA256SUMS for the **exact main commit**.
- GitHub APK/AAB use a disposable signer, **not the original Google Play upload key**. Do not use them to update an existing differently signed install or as Play production assets.
- Keep QA limitations explicit: actual physical-camera/OEM validation and original-reference 1:1 image comparison remain open.
