# QREX v1.0.44 — Android build 144

**Publication requires four successful exact-main-commit GitHub Actions workflows and authenticated Android emulator screenshots.** This release incorporates the six-screen alignment merged in PR #114 after the previously published v1.0.43.

## Visible Android changes

- **Result:** keeps bottom navigation visible; pinned Back action and scrollable QR content.
- **History:** compact records, category and timestamp hierarchy, five visible sample entries on the reference device with scroll and accessible large-font fallback.
- **More:** six responsive settings tiles with circular icon plates, translated captions and a separate destructive history action.
- **Create:** compact Link, Text, Wi-Fi and Contact quick choices; other supported QR formats remain available.
- **Scanner:** native scanner-corner symbol and retained CameraX, torch and gallery behaviors.
- **Splash:** native gradient/vector branding remains in use; the promotional artwork is not embedded as a screen.

## Verification and packages

- Production source metadata: `com.brendigo.qrex`, `versionName=1.0.44`, `versionCode=144`, `minSdk=26`, `targetSdk=36`.
- The release pipeline requires Kotlin/JVM, localization checks, security source checks, lint/R8, real Android screenshot capture and the API 26/31/34/35/36 connected test matrix before it publishes.
- Release assets contain an installable APK, a GitHub-only AAB signed with the same **disposable CI certificate**, an **unsigned Google Play QA AAB**, SHA-256 checksums and 12 real emulator PNG screenshots.
- **The disposable certificate cannot update apps signed with the existing Play or prior GitHub signing certificate.** No existing Play upload key is stored in source control or used for this public release. Do not upload its AAB to Play Console. Use the separately authorized production signing workflow.

## Pixel accuracy status

The six supplied images include a smartphone bezel and background around the app, not unframed, matching-density PNG screen captures. Therefore numerical pixel-perfect 1:1 equality is **not proven**. Genuine emulator screenshots, responsive viewport checks and in-app behavior are tested, but no 0% deviation is claimed. A live camera feed must remain real rather than replaced by a staged illustration.
