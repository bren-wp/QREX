# QREX v1.0.38 — Splash, Home / Scanner, Launcher

**Release candidate until merged, exact-main CI and GitHub publisher finish.**
Android application ID: `com.brendigo.qrex`; versionName `1.0.38`;
versionCode `138`. Last verified public release: v1.0.37.

## Scope: only the first two screens and launch identity

**01 Splash**
- Retain the canonical rounded blue Q / QR badge, four cyan scanner
  corners, split white/cyan QREX wordmark, localised three-word slogan,
  bottom footer and existing two diagonal native vector wave ribbons.
- Preserve original approved phone dimensions at **393×852dp**:
  214dp badge, 60sp title and unchanged wordmark/footer offsets.
- 800×1280dp tablet uses a responsive 256dp *same vector* logo,
  72sp wordmark and 20sp tagline rather than an undersized phone badge.
- Badge image clip and outside luminous cyan halo share the same
  proportional corner radius (22% of badge size) on all densities.
- Use vertically scrollable Splash on windows shorter than 700dp
  or at Android system font scale >=1.4. Footer always shows all
  translated text: no ellipsis hidden off the bottom.
- Real badge, localized text and loading track remain Compose elements,
  not background PNGs or generated mockup screens.

**02 Home / Scanner**
- Preserve CameraX PreviewView, local ZXing decoding, live viewfinder,
  one-time camera permission, gallery permission independence, bounded
  image decoding, frame closure, torch hardware-acknowledgement and zoom.
- Short-height windows (<620dp) and font scale >=1.5 use a *single
  vertically scrollable* Home rather than compressing the camera preview,
  Gallery and Torch action targets against the bottom navigation.
- In scroll mode the native camera viewport has a measured, responsive
  228–440dp at normal font scale (up to 520dp at 2× font scale). Normal-phone fixed layout retains flexible
  `weight(1f)` camera sizing and original controls.
- The scanner corner guide remains ~73% of camera width on regular
  phones, with 83% usable-height protection; on tablets its side
  length caps at **440dp** so it cannot become enormous.
- Camera content never changes to an illustrative photo or fake QR.

**03 Launch icon**
- Keep the selected QREX Q / QR symbol and approved gradient palette,
  not the alternative scanner-square visual used in another marketing
  composite. Do not change the Android application ID.
- Full-colour adaptive and monochrome themed foregrounds now share
  a 0.8-unit inset luminous contour, 0.91× safe-zone scaling,
  matching white Q/QR cell geometry and Android's round/squircle masks.
- Main and round launcher assets both point to the same foreground,
  background and monochrome drawables. Android 12+ startup remains
  tied to the canonical full-colour splash vector.

## Automated validation

- `QREXSplashLayoutTest`: 320×568 compact, 393×852 reference phone,
  800×1280 tablet, font 1.39/1.4/1.6, scroll and track bounds.
- `QREXScannerFrameTest`: standard/short/tablet finder, max-side cap,
  tiny invalid inputs, scroll threshold and preview dimensions.
- `tool/test_splash_brand_parity.py`: launcher mask consistency,
  exact canonical SVG-to-drawable geometry, responsive halo rules.
- `tool/test_scanner_reference.py`: real camera controls and responsive
  scroll/flex branch, never static bitmap in live preview.
- Entire existing Android Kotlin/JVM, lint/R8, screenshot capture, 23
  language catalog and P03 instrumentation on API 26, 31, 34, 35, 36
  must pass on the branch and again on the **exact merged main SHA**
  before the release is published.

**Accuracy limits:** the supplied visual boards include perspective
phone-frame mockups, mixed brand variants and a non-live camera scene.
They are not calibrated reference screenshot PNGs. A 0% pixel error
cannot be proven without a flat same-size, same-density reference
capture and pixel diff. OEM adaptive icon masks also vary by launcher.
The Android emulator screenshots included in GitHub releases are real
captures; no images are generated in ChatGPT.

**Signing:** GitHub distribution uses an ephemeral CI certificate.
Neither the released APK nor signed AAB is a drop-in update for a
Google Play installation signed by another key. The Play QA AAB is
labelled UNSIGNED and cannot be uploaded as a signed Play update.
