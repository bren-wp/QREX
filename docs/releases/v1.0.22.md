# QREX v1.0.22 — Google Play SDK and R8 modernization

**Android package:** `com.brendigo.qrex` · **versionName:** `1.0.22` · **versionCode:** `122` · minSdk 26 · targetSdk 36.

- **AndroidX Fragment warning:** explicitly select stable `androidx.fragment:fragment:1.9.1` instead of transitive deprecated `1.1.0`; verify the resolved **releaseRuntimeClasspath** rather than trusting source declarations.
- **R8 performance:** Android Gradle Plugin `9.0.1` with Gradle `9.1.0` enables optimized resource shrinking automatically when release code shrinking and resource shrinking are enabled, as they are for QREX. AGP 9 built-in Kotlin replaces legacy `org.jetbrains.kotlin.android`, with Kotlin Compose compiler aligned to AGP's `2.2.10`.
- **Safety:** no changes to QR formats, local History, Favorites, stored Wi-Fi/Keystore keys, package identity, API permissions, camera scanning or private offline workflow.
- **Release QA:** 23 locales; JVM/Android lint and R8 checks; release dependency version insight; ten genuine dark Android screenshots; Android API 26/31/34/35/36 connected instrumentation and lifecycle checks; exact-main signed APK/AAB; checksum/signature audit.

The GitHub packages use a disposable GitHub certificate and **cannot update** the differently signed Play installation. Google Play requires the existing authorized upload certificate via the separate protected signing workflow, followed by manual Console submission. Do not uninstall existing Play or GitHub installations to change certificates: local data could be lost.

**Status:** Release candidate until the exact-main GitHub workflow has published and verified all assets. Google Play warnings can only be considered addressed after submitting the correctly signed AAB and allowing Play Console to analyze it.
