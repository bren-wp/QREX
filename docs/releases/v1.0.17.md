# QREX v1.0.17 — Create QR, scanner and history stability

**Android:** `com.brendigo.qrex` · `versionName 1.0.17` · `versionCode 117` · minSdk 26 · targetSdk 36.

## What's improved

- **Create QR:** Resolved the blocking empty QR preview that could push the Generate and Save actions off-screen. The empty panel no longer appears; an actual QR preview lives inside the scrollable form, and both actions stay reachable in the pinned footer. Generation is enabled from a valid payload, without waiting for the bitmap.
- Preview bitmap generation is limited to visible, valid QR content when the keyboard does not obscure it, saving allocations and CPU.
- **Wi-Fi security:** PNG export uses the exact QR payload approved in the privacy confirmation, not a later edited draft; cancellation clears that approval.
- **Scanner:** Camera controls and QR guide avoid compact-screen overlaps, zoom presets reflect real device support, and large-font/gallery/torch actions remain accessible.
- **History and Favorites:** QR strings (including Wi-Fi credentials) no longer appear in Compose list-state keys. Cards have expanded large-font layouts.
- **Splash and branding:** Resolved short-screen and large-font layout clipping, synchronized the production Q/QR icon, and corrected localized screen-reader descriptions.
- **Result:** The pinned Back action announces the correct localized label.

## Installation, privacy and signing

GitHub APK and AAB binaries use a **disposable per-build certificate**. The
GitHub APK **cannot be installed as an in-place update** over an install signed
with a different certificate, including Google Play installs and earlier GitHub
versions. Do not uninstall merely to test an APK: this can erase local QR
history, saved favorites and Keystore-protected Wi-Fi credentials.

The public GitHub AAB is **not a Google Play upload artifact**. The separately
named `Play-UNSIGNED-QA.aab` is also **not signed or ready for Play**. The
existing Play upload certificate and authorized Play Console flow are required
for a Play update; this GitHub publisher never changes signing keys or
submits a store build.
