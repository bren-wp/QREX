# QREX v1.0.19 — five-tab native UI and broader clipboard privacy

Android package: `com.brendigo.qrex` · `versionName 1.0.19` · `versionCode 119` · minSdk 26 · targetSdk 36.

## What's new
- The dark Android QREX UI now has the five distinct working destinations in the provided reference: **Scan, Create, History, Favorites, More**.
- A dedicated Favorites destination searches only saved QR codes, while the existing History All/Saved filter remains available.
- Five-tab navigation uses responsive label sizing and maintains accessible, tested touch targets at narrow widths and large font scales.
- Android 13+ system clipboard previews now mark **all** copied QR contents sensitive, including private links, contact details and arbitrary text, while preserving copy/paste. This does not encrypt or automatically clear the operating system clipboard.
- **PDF export privacy:** a user-approved, in-memory-only snapshot of saved QR codes is captured before the Android document picker opens. Changes to Favorites or History while the picker is open cannot silently change the contents of the approved PDF.
- **Reliable preferences:** language and History settings are confirmed only after a durable write succeeds, with localized failure feedback instead of silently reverting after restart.
- Public README features all ten actual Android emulator captures from the verified previous release; this version produces its own ten genuine screen images for publication.
- Navigation, history storage, Wi-Fi AES-GCM/Keystore data, local-language catalog, CameraX scanning and offline QR creation remain preserved. No new permissions or network access.

## Signing and upgrade warning
**GitHub APK and AAB are signed with a disposable certificate**, not the approved Google Play upload identity. A GitHub APK cannot update an installation signed with another certificate. Do not uninstall an existing app without protecting local History, Favorites and Wi-Fi data; uninstall can irreversibly remove them. The included unsigned Play QA bundle is not Play-ready. An official Play update requires the already approved upload certificate and a separate manual signing/approval process.

The supplied dark, light and iOS-like marketing boards are perspective illustrations and not aligned test images; measured mathematical per-pixel parity is not claimed.
