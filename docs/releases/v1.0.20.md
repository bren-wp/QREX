# QREX 1.0.20 — consistent dark screenshots and responsive settings

**Android package**: \`com.brendigo.qrex\` · \`versionName 1.0.20\` · \`versionCode 120\` · \`minSdk 26\` · \`targetSdk 36\`.

## Improvements

- **Reliable midnight-dark release images.** All ten Play-sized screenshots come from the actual Android debug app with a dark-only screenshot override. An earlier saved Light/System theme cannot accidentally change a dark product image. This override never changes real user settings, and production builds do not accept screenshot fixture intents.
- **Real pixel verification.** In addition to checking the live app foreground and PNG dimensions, the screenshot and publication workflows now inspect real header-region PNG pixels and reject a bright/light frame labeled as dark. There is no synthetic image generation, OCR or cloud processing.
- **Compact Settings.** Six real functional cards use a three-by-two layout on standard 320dp and larger Android phones. Unusually narrow windows and accessibility font scales still use taller readable rows with normal scrolling rather than overlapping or clipping important actions. Main-screen padding is tighter and the destructive History action stays separately visible.
- **Correct public images.** QREX's README now shows ten actual screenshots from verified v1.0.19 while this candidate is being tested. Once v1.0.20 is published, those links should be updated to its own actual images.
- Scanning, Create, Result, History, Favorites, PDF/PNG export, Wi-Fi encryption and all 23 offline translations are preserved; app package name, data schema, encryption keys and permissions are unchanged.

## Mandatory publication checks

The GitHub publisher executes only after the **exact merged main commit** passes Android Kotlin/JUnit, Lint/R8, actual emulator screenshot+dark-pixel validation, all 23 localization checks and Android API 26/31/34/35/36 full instrumentation/lifecycle stress tests. It verifies version identity, Android APK signature and AAB signature, all ten real 1080x1920 images and SHA256 checksums. No GitHub release is published if any gate fails.

**Google Play signing:** GitHub APK/AAB use disposable per-release signing identities and are **not** authorized Play update packages. A Play update requires the existing authorized upload certificate via the separate manual, protected signing workflow and Play Console approval. Do **not** uninstall an existing version merely to install a GitHub APK, because local history, favorites and Keystore-protected Wi-Fi data may be lost.

The supplied marketing reference boards use perspective-transformed phones and are not exact pixel-diff targets. Native UI touch bounds, selected states, layouts and actual screenshot colors are objectively tested, but universal mathematically exact 1:1 similarity is not claimed.
