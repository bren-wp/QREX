# QREX v1.0.39 · build 139 — Splash viewport polish

**Release candidate until all checks pass.** Based on published v1.0.38.
Focus: **first screen (Splash)**, not changes to saved data or QR functions.

The genuine 1080×1920 emulator capture from v1.0.38 revealed a
visually important discrepancy: on shorter effective viewports the
scrollable Splash placed its footer/progress around the middle of the
screen, leaving excessive blank area at the bottom.

This update fixes actual Jetpack Compose layout geometry by ensuring
the inner scroll content has at least the real window viewport height,
then distributing the brand and footer vertically. The real QREX logo,
waves, responsive scale, wordmark, all 23 localized taglines, footer,
and progress bar are preserved. When long text does not fit, normal
vertical scrolling remains available, without clipping.

The instrumented Android test now explicitly rejects a compact
Splash footer that is more than 64dp from the bottom. Existing phone,
tablet and large-font unit tests continue to apply. See
[the screenshot-based audit](../audits/2026-11-07-qrex-v138-splash-capture-geometry.md).

Production boundaries: no changes to CameraX/ZXing, gallery, saved
QR records, Keystore protection, manifest, network permissions,
application package ID or launcher motif. Public GitHub release APK and
AAB will be signed by a disposable CI key and are **not** Google Play
upload-key updates; the Play-UNSIGNED-QA AAB is for inspection only.

The release is gated on full Kotlin/JVM, Android lint/R8, all 23
translations, Android API 26/31/34/35/36 30-cycle emulator tests,
genuine screenshots, all 16 nonempty artifacts and their checksums.

**Visual claim:** zero-pixel error against an original, flat phone
reference cannot be certified from a perspective-marketing composition.
