# QREX v1.0.36 — one-column premium Settings reference

**Release candidate; not yet published.** App ID `com.brendigo.qrex`,
versionName `1.0.36`, versionCode `136`; Android minSdk 26,
compile/target API 36.

## Screen-by-screen correction: More / Postavke

The largest confirmed structural gap is the existing **3×2 dark-mode tile grid**,
where the user explicitly requires every Settings action to appear in a
**single column, one full-width card below another**. Light mode already
used rows but did not share the same elevated 3D icon treatment. Both
appearances now use one consistent native Compose card stack:

- Theme, Language, Export, Privacy, Terms and About are presented in that
  order, each as a full-width standalone card with its existing live callback.
- Clear History is a seventh card with red destructive styling, an extra
  vertical separation, no misleading chevron and its existing confirm/cancel
  dialog. No QR history is changed merely by opening settings.
- One 15dp radius per card, native 3dp shadow, 72dp minimum touch height (88dp at ≥1.35× font scale),
  10dp vertical spacing, 14dp horizontal and 11dp vertical inner padding.
- Each card has a 40dp native vector icon plate with 12dp corner radius,
  a real white-to-transparent highlight, 4dp elevation and 22dp pictogram.
  Decorative layers have no competing clickable control or spoken label.
- Titles use 15sp semibold and supporting text 12sp. Content expands for
  long translated labels / large font; the screen remains vertically scrollable
  above the persistent bottom navigation.
- Retain theme/system selection, language preference, PDF export consent,
  privacy/history settings, Terms dialog and About/installed-version dialog.

## Verification and source quality

`tool/test_more_reference.py` and related source regressions assert the
single-column structure, unique real callbacks, icon depth and destructive
separation. `QREXMoreVerticalStackTest` verifies actual Android Compose
coordinates (both dark and light modes), aligned full-width touch cards,
no overlapping items, the separated destructive action, and the working
Privacy/Terms dialogs without changing history.

The Android CI must pass Kotlin/JVM, lint, R8/optimized APK/AAB, 23 offline
translations, P03 stress tests at API 26/31/34/35/36 and authentic 1080×1920
emulator screenshots on the **exact final main SHA**. The GitHub publisher
must then produce 16 nonempty verified assets: APK, AAB, unsigned Play QA AAB,
12 real PNGs and SHA256SUMS.

**Not yet proved:** mathematical pixel-for-pixel parity against marketing
collage images, physical-device usability at all DPI/font settings, Google Play
review, and official F-Droid acceptance. A perspective collage must first
be rectified into flat same-resolution reference crops to measure exact
pixel differences. No generated screenshot replaces a true emulator capture.

## Data, keys and upgrade warning

No change to package name, existing preference/history formats, old Flutter
migration, AES-GCM Keystore-protected Wi-Fi history, offline ZXing/CameraX
scanning, local PDFs or permission policy. CI GitHub packages use disposable
signing and cannot replace existing Google Play or differently signed GitHub
installations in-place. The unsigned Play QA AAB is **not** upload-ready.
An existing approved upload key and manual Play Console checks are required.
