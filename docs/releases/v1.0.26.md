# QREX v1.0.26 — Native screen fidelity, accessibility and privacy

**Package:** `com.brendigo.qrex` · **versionName:** `1.0.26` · **versionCode:** `126` · minSdk 26 · targetSdk 36.

This GitHub release candidate contains merged [PR #80](https://github.com/bren-wp/QREX/pull/80), including the following real native Compose improvements:

- **Favorites and History:** compact, accessible saved actions, validated navigation and saved-state behavior.
- **More / Settings:** two-column dark tiles with responsive single-row layouts on narrow, light-mode or large-font screens; confirm-before-clear History.
- **Language:** 23 offline languages plus system selection, aligned flag/radio rows, persistent selection and scrollable options.
- **Export:** pinned header, PDF action with disabled empty state, full-length local privacy warning, explicit consent and Storage Access Framework destination.
- **About:** QREX brand, actual installed app version, readable translated tagline and accessible Close / Open link controls.
- **Privacy:** readable scrollable disclosures, persistent local History toggle that does not delete existing data, and explicit full-policy action.
- **Responsive QA:** twelve real Android emulator screenshots, four additional About and Privacy responsive profiles; extended Python and Compose UI test coverage.
- **Security:** encrypted saved Wi-Fi records and local offline processing preserved, no new network permissions or analytics.

**Release gates:** exact-main-commit Android CI, localization, device API matrix, actual screenshot capture, R8/Lint, APK/AAB signing integrity and SHA256 checks. Source design work is not proof of mathematically identical pixels against marketing reference composites.

**Important signing caveat:** public GitHub APK and AAB packages are signed with a disposable CI certificate and **are not Google Play upload bundles**. They cannot upgrade Android installs signed with the original Play or another key. Avoid uninstalling an existing installation when you need to keep local history. Authorized Play distribution requires the protected existing upload key and its separate manual production workflow.
