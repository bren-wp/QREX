# QREX v1.0.16 — Android dark reference and CI stabilization

**Release candidate:** `com.brendigo.qrex` · `versionName 1.0.16` · `versionCode 116` · minSdk 26 · targetSdk 36. **Distribution:** GitHub release only after CI verification; not a Google Play update.

## Screens and usability

- Preserve the approved Android **midnight-blue Q/QR identity** from the supplied three QREX marketing compositions. The third image uses an alternate square scanner icon; the white Q/QR plus cyan brackets remains the actual Android adaptive launcher and in-app Splash symbol.
- Scanner: genuine on-device CameraX preview, cyan/white framing, permission-independent photo picker, real torch and zoom when available. No simulated screenshot backgrounds.
- Create: four primary QR types with real expandable advanced formats; actual preview, editable forms, Generate and Save actions remain functional and keyboard-safe.
- Result: centered review card and real Open/Copy/Share/Save/Delete actions; user is asked before opening external links or exporting Wi-Fi secrets.
- History / Saved: search now shows the **magnifying-glass glyph** from the reference instead of the clock glyph. Local history and Favorites filtering continue working.
- More / Language / Export: native About dialog retains installed version and Brendigo website action; PDF privacy notice is not truncated; the Language and Export Back button is a measured **52dp** control with **Back** label translated across all **23** offline languages.
- All screens share the existing dark responsive Compose design; no change in stored QR/history format, KeyStore AES-GCM protection, app ID or distribution key.

## Release pipeline fix

- Historical v1.0.4–v1.0.15 release jobs remain preserved for audit but now **skip without consuming GitHub runners** on new commits. v1.0.1–v1.0.3 already pin immutable published source SHAs. The new v1.0.16 publisher is the only enabled pending version-specific publication job.
- One release PR, one exact-head Android CI cycle, independent emulator captures and localization gates, and API26/31/34/35/36 lifecycle matrix. The publisher validates the exact current `main` commit, package/version metadata, APK/AAB certificate fingerprint equality, hashes, ten real 1080×1920 emulator screenshots and absence of prior v1.0.16 tag/assets.
- APK + AAB are signed with an **ephemeral disposable GitHub build key**; the AAB is **not a valid Google Play upload**. The separately labeled unsigned Play QA AAB is likewise not upload-ready. Google Play requires the original authorized upload key and separately confirmed Play Console policy/review.
- **No guaranteed in-place upgrade**: the GitHub APK signed with a disposable key may have a different certificate from earlier GitHub or Google Play installs. Do not uninstall without preserving important local data; uninstalling erases local QR History/Favorites and may make Keystore-encrypted saved Wi-Fi entries unrecoverable.

## Precise visual-acceptance limitation

The user-supplied source images are wide **marketing compositions with perspective-transformed phone mockups**, sometimes showing conflicting Android/iOS/light/dark concepts. They are not rectified, same-resolution screen-by-screen reference PNGs with matching Android system bars, language, QR data and font scale. Accordingly this release does **not claim** mathematical zero-difference (pixel-for-pixel 1:1). CI proves actual running Compose screen captures and responsive layouts; `tool/compare_ui_pixels.py` can perform quantitative per-screen pixel comparison once raw, matching-state images exist.
