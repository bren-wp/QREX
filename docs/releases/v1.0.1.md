# QREX 1.0.1 — Android stability, export and Play readiness

QREX is a privacy-first QR app for **Android only** (Kotlin / Jetpack Compose). Version **1.0.1**, `versionCode 101`, application ID `com.brendigo.qrex`.

## Improvements

- Reduced export memory pressure: PDF and ZIP generation stream into the user-chosen Android document destination instead of first buffering the complete PDF. Per-page QR bitmap allocations are released.
- Improved compact layout of Result screen copy/share buttons, including larger fonts and long translated labels.
- Audited Android permissions, dependency declarations, history migration, Wi-Fi Keystore encryption, URL safeguards, CameraX and gallery scanning.
- Rebuilt the Google Play upload workflow around 1.0.1 and a **real approved upload certificate** instead of obsolete 1.0.0 release/tag assumptions.
- Added verification for version progression, package ID, API 36 and privacy manifest; preserved 23 offline languages and existing QR formats.

## GitHub downloads

A GitHub `v1.0.1` release may include:

- `QREX-Android-1.0.1.apk` — Android release-mode APK signed using a disposable GitHub certificate.
- `QREX-Android-1.0.1.aab` — release-mode AAB signed with that same disposable certificate, **NOT a Google Play upload**.
- `SHA256SUMS.txt` — hashes of both public binaries.

**Important:** v1.0.0 was also signed with an ephemeral certificate that was not retained. Version 1.0.1 from GitHub uses a DIFFERENT certificate. Android cannot update one directly over the other, even though `versionCode` increases. Uninstalling an earlier copy may erase locally saved QR data. Export anything important before changing signing identities. Neither disposable-key AAB should be submitted as an update to an existing Play app.

## Correct Google Play AAB

For Google Play, manually run `QREX 1.0.1 — authorized Google Play AAB` with the existing approved upload-key secrets and completed device/store QA. It produces a **separate** Play-authorized `QREX-Android-1.0.1.aab` artifact and SHA-256 file without publishing those credentials or rewriting the GitHub release.

Google Play submission and Play Console approval are **not** completed merely by a successful GitHub build. The developer must review the merged manifest, Data safety, privacy policy, app content declarations, store listing, real-device QA, signing continuity and release track.
