# QREX v1.0.48 — Android build 148

**Status:** GitHub publication must pass all checks before this version is marked released.

## Encrypt all local QR history — migration-safe

- Extend the existing Android Keystore AES-GCM storage envelope to every QR history payload, not only Wi-Fi secrets.
- Retain the v1 Keystore alias, ciphertext format and per-record \`protected\` flag, preserving previously saved credentials and QR data.
- Convert plaintext history from older native builds in one durable commit, preserving record order, timestamps and favorite flags.
- Encrypt imported legacy Flutter QR entries before committing native history and removing the original legacy key.
- Reuse unchanged authenticated ciphertext so new scans encrypt only newly added records.
- Refuse automatic history writes if any encrypted record is corrupted or cannot be decrypted; an explicit user action remains required to delete the original data.
- Reuse an Android Keystore key handle within the running process to reduce repeated key-store lookups during 250-item migration.

## Tests and quality

- Extend Android instrumentation tests for URL, text, vCard, geo and Wi-Fi history encryption; legacy migration; restart idempotency; and corrupted non-Wi-Fi history.
- Preserve existing UI, CameraX/ZXing scanning, 23 locales, API 26+ compatibility and the same package ID \`com.brendigo.qrex\`.
- Require the existing exact-commit CI, Android device/emulator tests, R8/Lint, 12 genuine screenshots, artifact verification and signing rules before any publication.

## Distribution and rollout constraints

This is a **candidate**, not evidence of a published APK/AAB. The GitHub publishing pipeline currently signs with a disposable certificate, which cannot provide reliable in-place upgrade continuity. Do not replace the authorized Google Play upload key, claim Play/F-Droid publication, or recommend uninstalling existing installations. Confirm real-device performance for 250-record migration before declaring the build stable.

QR exports remain readable PDF/PNG files. User-authorized shares and clipboard operations intentionally hand readable QR data to the target app.

## Responsive and functional UI refinements (same PR)

- **History and Favorites:** a clear-search action appears only when a query is
  present, uses a real 48dp hit target and never changes saved QR contents.
- **Create Event:** date buttons retain the 2-column reference at regular
  393dp/1x scale, but stack at <390dp or >=1.30x font scaling. The form gives
  localized feedback if the end time precedes the start.
- Added pure window-class tests, actual Compose UI checks for date-button
  geometry and Search clearing, and source-level regression guards.
- Existing Splash, Camera, Result, More, Language, Export and Privacy behavior
  remains covered by previously established screen tests; pixel-level 1:1
  matching is **not yet verified** without flat aligned references.
