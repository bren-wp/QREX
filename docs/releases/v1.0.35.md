# QREX v1.0.35 — robust positioned CameraX Y-plane decoding

**Release candidate. Do not publish before all mandatory exact-commit CI tests pass.**
App ID `com.brendigo.qrex`; `versionName 1.0.35`;
`versionCode 135`; `minSdk 26`; `compileSdk/targetSdk 36`.

## Changes

- Fixed offline ZXing/CameraX camera QR decoding on Y-plane `ByteBuffer` views
  whose valid image begins at a nonzero position. Previously a `rewind()`
  shifted the source window, potentially producing invalid QR input.
- Reject truncated buffers and overlapping Y-plane rows using bounded
  long-arithmetic index checks before allocating an output byte array.
- Optimize the frequent packed Y-plane layout with row-wise bulk copies,
  maintaining safe per-pixel reads for non-unit strides.
- Preserve the caller's original buffer position and limit; no frame data,
  QR payload or image is transmitted to an external service.
- Added three Kotlin/JVM regression cases for packed/padded, direct/interleaved
  and truncated/overlapping Y planes.
- Updated native Android build and distribution documentation to reflect
  CameraX/ZXing, AGP 9.0.1, Gradle 9.1.0, JDK 17, F-Droid limitations and the
  distinct GitHub versus Google Play signing identities.

## Unchanged

Android `applicationId`, 23 offline locales, QR format support, five-tab UI,
accessibility patterns, encrypted Wi-Fi QR history, legacy Flutter migrations,
permissions, signed Play upgrade path and local user settings remain unchanged.
No claim of measured 1:1 UI parity is made because the UI was not altered.

## Release quality gate

The publisher must validate exact main SHA, Kotlin/JVM, Android lint/R8,
P03 emulator API 26/31/34/35/36, 23 languages, and genuine Android screenshot
capture before it can create a new immutable tag. Required assets: signed
GitHub APK and AAB (disposable GitHub certificate), a separately
**unsigned Play QA AAB**, SHA256SUMS with verification and 12 real 1080×1920
emulator PNG screenshots. Never mislabel the GitHub key as a Play upload key.

**Upgrade compatibility:** a disposable signing certificate does not permit
an in-place update of an earlier GitHub or Google Play installation. Uninstalling
can destroy local history and Android Keystore-backed Wi-Fi QR contents.
Google Play submission requires the original approved upload signing key,
physical-device upgrade checks and manual review.

The official F-Droid submission/acceptance and pixel-exact reference
matching are **not verified** by these checks.
