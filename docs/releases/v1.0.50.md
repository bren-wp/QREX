# QREX v1.0.50 — Android build 150

**Status:** Candidate pending exact-commit verification. GitHub publication must pass all checks before this version is marked released.

## Document scanner and PDF workflow

- Add document scanning inside the existing Scan tab using CameraX capture and Android Photo Picker without requesting broad file storage permission.
- Enable manual quadrilateral perspective cropping and rectangle cropping with four draggable corners, a high-contrast overlay and alignment grid.
- Offer a conservative offline page-boundary suggestion; manual adjustment is always available when the page cannot be detected reliably.
- Allow complete crop reset, one-step undo of last edit, 90-degree rotation, grayscale and high-contrast monochrome enhancement.
- Capture, import, reorder, re-edit and delete up to eight pages; export portrait/landscape A4 multi-page PDFs using Android's system save dialog.
- Honor imported JPEG EXIF rotations/mirroring; bound in-memory page dimensions and avoid unintended cache persistence.

## Design and accessibility

- Retain the native QREX dark-first visual language and existing five-tab navigation.
- Place accessible, labeled 48dp action targets for reordering, editing and deleting pages; keep layout responsive on small displays.
- Add verified real-app screenshot capture fixtures for Review, Crop, Pages and PDF Export in both dark and light modes.
- Extend the exact pixel comparator with explicit document-state and light/dark reference selection; a 1:1 claim requires original matched reference images.
- Localize document editor, enhancement and auto-boundary actions in all 23 supported languages.

## Verification and distribution

- Package: `com.brendigo.qrex`; Android versionCode 150 / versionName 1.0.50; minSdk 26; targetSdk 36.
- Require successful Kotlin build, JVM tests, Android instrumentation on API 26/31/34/35/36, Lint, R8, privacy/security checks, 23-language validation and genuine screenshot capture for the exact merged main commit.
- The GitHub publisher produces a signed APK, an AAB signed with a disposable GitHub key (not Play-ready), a separate unsigned Play QA AAB, screenshots and SHA-256 checksums only when all automated gates pass.
- A disposable GitHub signature **cannot update** an existing app installed through Google Play or a differently signed APK. A Google Play update needs the separately protected existing Play upload key and manual production approval.
- PDF exports are not encrypted. Imported paper documents stay in volatile process memory until explicit export; session is lost after process death.
- No release tag, binary or claim of pixel-perfect parity may be created merely from a green compile: screen references, device validation and downstream quality gates remain obligatory.
